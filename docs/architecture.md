# Architecture

The owner's settled decisions. Changing one is an owner decision, not something a pull request does on its own.

- **One repository for operations and money.** The former effect-finance repository is merged in: its payments core is core's `./Payments*` subpaths and its Stripe provider is `@thomasfosterau/effect-biz-payments-stripe`. The ledger, chart of accounts, journals, invoices, bills, credit notes, AR/AP, tax and financial reports are built here alongside parties, the catalogue, sales, purchasing, inventory, manufacturing, CRM, HR, projects and payroll. A monetary primitive (`Money`, `Currency`, a tax code) lives in core once.
- **Master data lives here.** Parties (customers, suppliers, contacts, addresses) and the catalogue (products, services, units, price lists).
- **Persistence: ports and adapters.** Each domain package defines its repositories as `Context.Service` interfaces, with an in-memory layer for tests and an `effect/sql` layer. Postgres and Cloudflare D1 are production dialects; SQLite serves tests and embedded hosts. A host may supply its own layer.
- **Commands are load → decide (pure) → commit one atomic batch** of version-guarded writes, retried from `load` on a guard conflict. D1 has no row locks or interactive transactions, so this holds on every dialect. The host chooses a shared database or one per tenant through a `TenantDatabase` resolver.
- **Tenancy: tenant + company.** Every repository call runs under a `TenantContext` (every row carries `tenant_id`); a tenant holds companies (legal entities), each with its own base currency, fiscal settings, warehouses and numbering. The host provides the context per request.
- **Integration: domain events + transactional outbox.** Events are written to an outbox in the same transaction as the state change; cross-module effects are idempotent subscribers; long-running flows run on `effect/workflow`. Events can be forwarded as CloudEvents (signed webhooks, Cloudflare Queues, AWS SNS/SQS, Kafka, NATS).
- **Surfaces: services, JSON:API and `effect/rpc`.** Each domain package exposes services and layers, plus optional HttpApi (JSON:API v1.1 on `@thomasfosterau/effect-jsonapi`) and RPC groups. A client package provides typed clients and legation resources (legation an optional peer of that package only). No UI.
- **Authorisation: effect-auth.** Commands are authorised by `@thomasfosterau/effect-auth`'s `Authorizer` (`"resource:action"` actions, `EntityRef` resources); effect-biz has no policy engine and does no authentication. Tenancy is independent of effect-auth Organizations.
- **Commercial documents** carry their own currency plus base-currency amounts at the document-date rate; inventory is valued in base currency. Prices are tax-inclusive or exclusive per price list or document; the rounding basis is a company setting. Sales channels plug in through a `SalesChannel` port.
- **Documents and reporting.** Modules emit typed document data, rendered to HTML/PDF from host-overridable templates. Standard reports are event-fed projections behind a typed query API in core.
- **Privacy.** Personal data is annotated in schemas; core provides data-subject export, anonymisation with legal holds, retention schedules and a sensitive-field access log. An annotated field is never logged or emitted.
- **Import and migration**: a core import framework plus migrators (Xero, MYOB, Shopify, Odoo/ERPNext); financial history migrates into the ledger.
- **Localisation: neutral core, Australia first.** Domain packages are jurisdiction-neutral with extension points; the first locale package is Australian (ABN/ACN, addresses, NES leave, PAYG withholding, superannuation, Single Touch Payroll payloads).
- **Payroll: calculation and export, not lodgement.** Pay runs, their ledger journals and STP-ready payloads; lodging with the ATO is an adapter's or the host's job.
