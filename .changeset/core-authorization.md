Add authorisation through effect-auth's policy kernel (#130). `@thomasfosterau/effect-biz/Authorization` is the one subpath that imports `@thomasfosterau/effect-auth`, a new optional peer (`^0.2.0`). `authorize(action, resource)` asks effect-auth's `Authorizer` whether the `CurrentPrincipal` may perform a `"resource:action"` action on an `EntityRef`; a denial is `BizError.Forbidden` and any other Authorizer failure is `Unavailable`. `catalogue` declares a module's actions (`company` is core's: `company:create`, `read`, `update`, `archive`, `restore`), and `fragment` / `model` build effect-auth's `AuthorizationModel` from catalogues. `composeResolvers` / `layerResolvers` build one `EntityResolver` from per-type module resolvers, resolving transitive ancestors across them. `toActor`, `currentActor`, `withActor` and `layerActor` derive `Actor.CurrentActor` from the `CurrentPrincipal` (system principals become system actors). `layerPermissive` is an `Authorizer` that allows everything, for tests. `BizError.Forbidden` gains an optional `trace` (`Option<DecisionTrace>`, an omitted key on the wire): the decision's reason and its determining policies (`DeterminingPolicy`), never the principal.
