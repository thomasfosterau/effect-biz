Add the SQL unit of work and repository helpers (#39). `@thomasfosterau/effect-biz-sql/SqlUnitOfWork` builds core's `UnitOfWork` over `effect/sql` with no interactive transactions (#128): each command's staged `Write`s (a statement and its `Guard`, built with `guarded` / `unguarded` and `stage`) commit as one atomic batch, in one `withTransaction` on Postgres and SQLite (counting each guarded statement's returned rows) and as one `Batch` on D1, where each guarded write is followed by a guard statement that raises when unmet; an unmet guard rolls the batch back and fails with `ConcurrencyConflict`, retried from load by core. `layer` picks the commit from the dialect (on D1 it needs the host's `Batch`, else `BatchRequired`), `layerBatch` states the batch commit, and `Committer` is the commit a repository captures. `@thomasfosterau/effect-biz-sql/SqlRepository`'s `make` builds a whole `Repository.Port` over one table: tenant-scoped reads decoded through `Schema`, writes decided eagerly and staged version-guarded, the audit columns stamped with `Audit.next`, and `find` translating core's `Query` into `WHERE` / `ORDER BY` over an allow-list of columns (`Kind`), with keyset paging on core's own cursors. `./testing` adds `layerBatch`, D1's batch semantics over a client with transactions.
