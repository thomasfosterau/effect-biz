Add the unit of work (#29). `./UnitOfWork` defines the `UnitOfWork` service and its `transaction` accessor: a service wraps each command in it, the command's writes are staged (version-guarded) and committed as one atomic batch when it succeeds, nothing applies when it fails or is interrupted, nested transactions join the outer one, and a batch whose guard fails at commit is retried from the load step with bounded, jittered exponential backoff before failing with `ConcurrencyConflict` (`Options`: `attempts`, `backoff`). `makeJournal`, `stage` and `make` let another implementation (a SQL layer) stage its own write type; `layerMemory` / `makeMemory` commit the in-memory stores' writes in one `Effect.tx`. `./Memory` stores are now `TxRef`s: `Memory.modify` is replaced by `Memory.put` (one row guarded by the version it must still be at, staged into the open transaction or committed at once), and `makeLog` / `append` / `entries` add an append-only, outbox-shaped store; reads see committed rows only. `./testing` adds `unitOfWorkContract` and `UnitOfWorkSubject`, the runner-agnostic suite for a unit of work over a repository and an event log.
