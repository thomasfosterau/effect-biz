# @thomasfosterau/effect-biz-payments-stripe

## 0.1.0

### Minor Changes

- [#192](https://github.com/thomasfosterau/effect-biz/pull/192) [`5d98b2d`](https://github.com/thomasfosterau/effect-biz/commit/5d98b2d1649ae349d9f364bad8ac42e54e1a32d4) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Vendor response bodies are typed as `Schema.Json` where they cross a decode boundary instead of `unknown`. `WebhookEvent`'s `data.object`, and `decodeCheckoutSession` / `decodeSubscription` / `decodeInvoice`, take `Schema.Json`; `StripeHttp.call` resolves to `Schema.Json`, and a 2xx now succeeds with the JSON body the client observed rather than Distilled's decoded output. In core's internal REST helpers (exempt from semver), `ObservedResponse.body` is `Option<Schema.Json>` and the `responseDecoder` decoders take `Schema.Json`.

- [#203](https://github.com/thomasfosterau/effect-biz/pull/203) [`e1bcada`](https://github.com/thomasfosterau/effect-biz/commit/e1bcada94a33dd4b5fb9bc28f49058baf5453929) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Absence is an `Option` and a parameter bag member is a bare `?: T`: `T | null` and `T | undefined` no longer appear in the payments types.

  Core entity fields that were `T | null` are now `Option<T>` (their encoded form is unchanged: `Schema.OptionFromNullOr` still reads and writes `null`). `Customer`: `email`, `name`, `phone`, `description`. `Product`: `description`. `Price`: `productId`, `unitAmount`, `recurring` (an `Option<Recurring>`). `PaymentIntent`: `customerId`, `paymentMethodId`, `clientSecret`, `description`. `Subscription` item: `quantity`. `Refund`: `paymentIntentId`, `chargeId`, `reason`. A provider builds them with `Option.fromNullishOr`; a consumer reads them with `Option.match` / `Option.getOrElse`.

  `Page.nextCursor` is now a required `Option<string>` (`Some` when `hasMore`), not an optional `string`; pass its value on as the list params' `startingAfter`. A provider's page literal must set it (`Option.none()` on the last page).

  Every `CreateParams` / `UpdateParams` / `ConfirmParams` / `ListParams` member (and `CheckoutSession` line items' `quantity`, and `Price.CreateParams["recurring"]`'s `intervalCount`) is declared `readonly x?: T` instead of `readonly x?: T | undefined`. Under `exactOptionalPropertyTypes` a caller holding `undefined` now omits the key rather than passing it.

  `IdempotencyKey.validate` takes an optional `key?: string` and resolves to `Option<IdempotencyKey>` (`None` for no key) instead of `IdempotencyKey | undefined`.

  Stripe: `StripeHttpConfig`, `LayerConfigOptions`, `RequestOptions` / `CallOptions` and `Webhook.VerifyOptions` / `WebhookConfig` members drop `| undefined` (`VerifyOptions.header` is now `header?: string`: omit it, rather than pass `null` or `undefined`, when the request carried no `Stripe-Signature`). The raw resource modules' trailing `options?: RequestOptions` is unchanged. In the semver-exempt `Payments.internal`, helpers that answered `T | undefined` (`scaleToMinor`, `parseDecimal`, `formatDecimal`, `stringField`) answer `Option<T>`, `epochSecondsOf` takes an `Option<string>`, and `pageNumberedList` takes its params as a required object and lists with `(page?: number)`.

  Error classes: every field that may be absent is now an `Option` (`Schema.OptionFromOptionalKey`, so the encoded form, over the wire and RPC, is still an omitted key; a constructor call may leave the field out, which is `None`). The fields: `PaymentProviderError` `code`, `statusCode`, `cause`; `PaymentAuthenticationError` `statusCode`; `PaymentRateLimitError` `retryAfter`; `PaymentInvalidRequestError` `param`, `statusCode`; `PaymentNetworkError` `cause`; `PaymentsUnavailable` `provider`; `SignatureVerificationError` `header`, `payload`; `BusinessRuleViolation` `details`. Pass `Option.some(x)` to set one and read it with `Option.match` / `Option.getOrElse`.

- [#155](https://github.com/thomasfosterau/effect-biz/pull/155) [`9459bf4`](https://github.com/thomasfosterau/effect-biz/commit/9459bf470cfea345143ac7d7ed68db50be9877bf) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Absorb the effect-finance repository's payments packages, none of which was ever published. The vendor-neutral payments core (formerly `@thomasfosterau/effect-payments`) is now part of `@thomasfosterau/effect-biz`: import the barrel from `@thomasfosterau/effect-biz/Payments` and each module from `@thomasfosterau/effect-biz/Payments.<Module>` (`Payments.Customer`, `Payments.Subscription`, …; the providers' shared helpers are `Payments.internal`). The Stripe provider is now `@thomasfosterau/effect-biz-payments-stripe`, versioned in lockstep with the rest of the family (effect-finance's PayPal and Airwallex providers were not carried over). Its behaviour is unchanged; the `Context.Service` and `Schema.Class` identifiers move from `@effect-payments/…` to `@effect-biz/payments/…`.

### Patch Changes

- [#174](https://github.com/thomasfosterau/effect-biz/pull/174) [`19496e8`](https://github.com/thomasfosterau/effect-biz/commit/19496e83d1d3b4e6834fb82ba42950edda57625c) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Move Distilled (`@distilled.cloud/stripe` and `-core`) from `1.0.0-rc.15` to `1.0.0-rc.18`, and the optional `stripe` dev pin to 23.0.1 (still `2026-09-30.endive`, so `DISTILLED_API_VERSION` is unchanged). Distilled rc.16 and later declare `effect: ^4.0.5`, so the Stripe provider's `effect` peer range moves from `^4.0.0` to `^4.0.5` (its own `catalogs.distilled-peers`): a range change only, tested at effect 4.0.5. The core stays `^4.0.0`. With rc.18 Distilled keeps its schemas private, so the Stripe resource modules now re-export Distilled's input and output types as types only (reach an operation's schemas through its `input` / `output`). A 2xx whose body is not JSON still fails with `PaymentProviderError` ("Invalid JSON received from the Stripe API") although Distilled now fails such a response with its own `StripeParseError`, and a `ConfigError` from Distilled's `Credentials` in context surfaces from the Stripe client as `PaymentsUnavailable`.

- [#187](https://github.com/thomasfosterau/effect-biz/pull/187) [`1a93ba9`](https://github.com/thomasfosterau/effect-biz/commit/1a93ba9404864fbe72869a3efda163b7613854ad) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Payments schemas no longer use `Schema.Number`. Minor-unit amounts (`Money.amount`, `unitAmount`, refund and payment-intent amounts), quantities, interval counts, epoch-second timestamps and HTTP status codes now decode with `Schema.Int`, and `PaymentsError.retryAfter` with `Schema.Finite`. Decoding therefore rejects `NaN` and `Infinity`, and rejects fractional values wherever `Schema.Int` applies; the same holds for the Stripe mapping and webhook schemas.

- [#160](https://github.com/thomasfosterau/effect-biz/pull/160) [`9e4bb7c`](https://github.com/thomasfosterau/effect-biz/commit/9e4bb7ca1f355236770bc5409614d4a8600da8c2) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Tidy emitted signatures found by type-aware linting, with no change in what they accept: optional parameters drop a redundant `| undefined` (an optional parameter already accepts `undefined`), including every generated Stripe resource operation's `params?` and `options?`, and `Redacted.Redacted<string>` is written `Redacted.Redacted` (its default type argument).
