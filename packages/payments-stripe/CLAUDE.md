# @thomasfosterau/effect-biz-payments-stripe

Stripe: the neutral capabilities as `Layer`s (`StripePayments`) over Distilled's generated Stripe operations (`@distilled.cloud/stripe`, effect-finance#146), plus one resource module per Stripe API resource as a provider escape hatch: a thin wrapper of every Distilled operation on the resource, run through the same client (`StripeHttp`). Peers: `effect` at `^4.0.0` (`catalogs.peers`, which is also Distilled's own peer range), and `stripe` **optional** (only the types of the SDK-based webhook verifier, `Webhook.constructEvent*`, which runs on an SDK client the program provides; nothing loads it). Dependencies: the core, `@distilled.cloud/stripe` and `@distilled.cloud/core` (both pinned exactly in the catalog, at the same version).

## Boundary

Imports only `@thomasfosterau/effect-biz` (its `./Payments` and `./Payments.<Name>` subpaths) from this workspace. Distilled is imported only by `StripePayments.ts`, `StripeHttp.ts` and the generated resource modules, and only through its subpaths (`@distilled.cloud/stripe/stripe` for the operations, `/Credentials`, `/Protocol`, `/Retry`, `@distilled.cloud/core/response-validation`; `scripts/` also reads `@distilled.cloud/core/protocol-http` and `/trait`). The declarations of `StripePayments`, `StripeHttp` and `Webhook` name `@distilled.cloud/stripe/Credentials` and nothing else of Distilled's, because the operations' module is a 7.5 MB declaration every consumer would type-check; the resource modules (and the `Treasury` and root barrels) name the operations' module by design, the price of the escape hatch (`tests/dist-consumer/src/distilledDeclarations.ts`).

## Invariants

- **`layerConfig` never fails to build.** `StripeHttp.layerConfig` (and `StripePayments.layerConfig`, over the same client) reads the key (`STRIPE_API_KEY` by default) on every call, never at layer construction: from the calling fiber's `ConfigProvider` first, then from the one the layer was built under (so a provider attached with `Layer.provide` is honoured). Absent, empty or unreadable, the call fails with the core's `PaymentsUnavailable` before anything is sent. Effect's `ConfigProvider` treats a literal empty string as a missing value, so an empty `STRIPE_API_KEY` is read as absent by the provider itself; the code's own empty check stays as the guard for a `ConfigProvider` built with `preserveEmptyStrings: true`. `layerFromEnv` likewise fails with `PaymentConfigError` for an empty variable (`tests/StripeHttp.test.ts`, `tests/StripePayments.layerConfig.test.ts`). This is gardeneria's `stripeStubLayer` / call-time `STRIPE_SECRET_KEY` posture ("not configured ≡ down"). `layer` / `layerFromEnv` keep failing the build with `PaymentConfigError`.
- **Stripe failures become neutral errors in one place**: `toPaymentsError` (`internal/error.ts`), fed by `classifyResponse` (status + the `Schema`-decoded `{ error: { type, code, message, param } }` envelope, 401 / 403 / 429 winning over the body's `type`, as in the SDK) from the client (`StripeHttp`). Distilled's error classes carry neither the status nor the whole vendor error object, so the client watches each response through the `HttpClient` it hands Distilled and classifies that; a Distilled failure with no response behind it is a connection failure or a `PaymentProviderError` coded by its tag. A resource module or capability never throws and never leaks a Distilled error class (`tests/resources.wire.test.ts` maps an error and a malformed 2xx for every module).
- **Every request pins `Stripe-Version`, following Distilled** (`DISTILLED_API_VERSION` in `internal/apiVersion.ts`, re-exported from `StripePayments.ts` and `StripeHttp.ts`; unless configured, or overridden by a resource-module call's `RequestOptions.apiVersion`; through `withRequestOptions`): Distilled sends none of its own. Owner decision on effect-finance#146: the pin is the API version the pinned Distilled release's schemas are generated from (`2026-09-30.endive` at `1.0.0-rc.15`: the `com.stripe.api#Stripe` service's `version` in `packages/stripe/.generated-specs/stripe.json` at the release commit; the tarball has no such constant), and it **moves with every Distilled bump**. `tests/distilledApiVersion.test.ts` keys the followed version by the installed Distilled version and fails on a release it does not list: on a bump, update the constant and that table together, re-check the fields `internal/mapping.ts` reads, regenerate the resource modules, and move the strictly decoded fixtures (`tests/fixtures/endive/`, `tests/StripePayments.endive.test.ts`) to the new version. The `stripe` dev pin follows it too (effect-finance#160): the same test fails unless the installed SDK's `Stripe.API_VERSION` equals the constant, so a bump also moves the `catalog:` pin to the stripe-node release for the new version, and the optional peer range in `catalogs.peers` with it. Distilled's schemas mark fields required that a response at an older configured version lacks, so the client also pins Distilled's `ResponseValidation` to lenient and the capability layers decode the fields they map (`internal/mapping.ts`); the resource modules return the response unvalidated. Distilled's own retries are switched off; the client applies the SDK's policy, a per-attempt timeout and redirect refusal itself (`tests/StripePayments.wire.test.ts`, `tests/StripeHttp.test.ts`).
- **Top-level layer constructions in `StripePayments.ts` are `/* @__PURE__ */`, and the capability modules are namespace imports by subpath**, so a bundler drops the capabilities (and the Distilled operations, with their schemas) a program does not use. A named import from the core's barrel turns `CustomerNS.Customers` into a property access a bundler must keep. The same holds for `internal/mapping.ts`: every top-level wire schema and decoder is a `/* @__PURE__ */` call, nested calls included, over `import * as Schema from "effect/Schema"` and the core's modules by subpath (a named `{ Schema }` import from `effect` keeps every schema), so one capability's decoders never stay in a bundle that imports another (effect-finance#149).
- **Nothing loads `stripe` at runtime.** Only `Webhook.ts` imports it, with `import type`, for the SDK-based verifier, which runs on the client the program provides as `Webhook.StripeService`; so a Worker bundle never contains the SDK. `tests/sdkOptional.test.ts` walks the sources' runtime import graph and `tests/dist-consumer/src/sdkOptional.ts` (in that package's `check` task) walks the emitted `dist/` graph; either fails otherwise. `tests/dist-consumer/src/declarationsFreeOfSdk.ts` checks that no declaration but `Webhook`'s (and the root barrel's) names it.
- **Every call needs a `process` global** (on Workers, `nodejs_compat`; owner decision on effect-finance#146: document it, no shim). Distilled reads `process.env.DISTILLED_DEBUG_HTTP` unguarded each time it encodes a request or decodes a response (effect-finance#148), so without one a capability or resource-module call dies with a defect. Building a layer, and a `layerConfig` call with no key, never reach Distilled; `Webhook.verify` never loads it.
- **The key never reaches an error or a log line.** It is a `Redacted` until the header is set; a transport failure's `cause` is the underlying error, never the `HttpClientError` or `HttpClientRequest` (whose headers carry the key). `tests/StripePayments.wire.test.ts` walks every error's own-property graph for the key, because Effect's `Headers` redaction hides it from `JSON.stringify` and `String`. Distilled's `DISTILLED_DEBUG_HTTP` logging does not log the `Authorization` header, but does log URLs and bodies (a `client_secret` included).
- **Inputs bound for Distilled or the SDK go through `omitUndefined`** (`@thomasfosterau/effect-biz/Payments.internal`, shared with PayPal): their types declare bare `?: T`, which `exactOptionalPropertyTypes` will not let an assembled `T | undefined` satisfy. The resource modules take Distilled's input types as they are, bare `?: T` included (a thin re-export); Distilled's encoder skips `undefined` members.
- **Never hand-edit a resource module.** `src/<Resource>.ts` is written by `generate:resources` (`scripts/generate-resources.ts`) from the installed Distilled release and `scripts/resources.ts` (which operation goes in which module, under which name); `tests/resources.test.ts` fails when a module on disk differs from the generator's output, when a Distilled operation is neither placed in a module nor listed in `UNEXPOSED`, when an operation beyond the two deliberately unexposed ones is left out, when a resource module is missing from the root barrel (or, for a `Treasury.*` one, the `Treasury` barrel), and when a name a module had before effect-finance#146 disappears. On a Distilled bump, rerun the generator and settle what the test reports in `scripts/resources.ts`. **Every resource has a subpath** (owner decision on effect-finance#154): at Distilled `1.0.0-rc.15`, 131 resource modules wrap 587 of its 589 operations. A new Stripe resource gets a `RESOURCES` entry (named after the SDK's resource type, dotted for a namespace: `Billing.Meter`, `V2.Core.Account`), an `exports` entry, a line in the root barrel (or the `Treasury` barrel) and the README's list, and a regeneration. `UNEXPOSED` holds only what `StripeHttp`'s request policy cannot run, each entry with its reason: `GET /v1/quotes/{quote}/pdf` (a binary PDF from `files.stripe.com`, where the client reads every 2xx as JSON) and `POST /v2/billing/meter_event_stream` (`meter-events.stripe.com`, authenticated by a session token, not the key). An entry longer than a resource's path wins over it.

## Terms

- **Client** — `StripeHttp` (`StripeHttp.ts`, a `Context.Service` whose `call(method, operation, input, options?)` runs one Distilled operation under the request policy above and resolves to the response JSON, unchecked; `options` is a `RequestOptions` plus `upload`, which sends the request to the uploads origin, `files.stripe.com` unless configured; the resource module flattens an upload's nested params into bracketed keys first, since Distilled's multipart encoder would send them as JSON parts Stripe does not read; a `DELETE`'s params, which Distilled form-encodes into a body, are moved to the query string, as the SDKs send them, by `internal/deleteQuery.ts`, `tests/StripeHttp.test.ts` and `tests/deleteQuery.test.ts`; a `/v2` request, told by its URL under the configured origin, gets stripe-node's `/v2` policy from `internal/v2Request.ts`: array query params indexed (`include[0]=a`, where Distilled repeats `include[]`) and a `DELETE` keyed, effect-finance#181). Built from Distilled's `Credentials` in context (`layerFromContext`, what the capability layers use), or from configuration (`make` / `layer` / `layerFromEnv` / `layerConfig`): `Redacted` key, `Stripe-Version` pinned, redirects refused, the SDK's retry policy and backoff with one generated `Idempotency-Key` across the attempts of a `POST` or a `/v2` `DELETE` (never a `/v1` `DELETE`, as in the SDK), every failure mapped onto `PaymentsError`.
- **Resource module** — `Customer.ts`, `Treasury.FinancialAccount.ts`, …, generated (see the invariant above): one export per Distilled operation on the resource, `operation(Distilled.X, { method, path, ids, params, upload? })` (`internal/resource.ts`) annotated with its signature: the path ids as strings in path order (each refused unless a non-empty string; Distilled URI-encodes it), then `params` (the rest of Distilled's input, `Omit<XRequest, ids>`, with `PARAM_TYPES` in `scripts/resources.ts` retyping a member Distilled declares too narrowly: `File.create`'s `file` as `string | Blob`; an entry whose operation, or whose member, Distilled no longer has is a plan problem; omitted when there is none, optional unless a member is required), then `options?: RequestOptions | undefined` (`{ idempotencyKey?, stripeAccount?, apiVersion? }`; only those three fields are read). Each module also re-exports its operations' Distilled input and output types and schemas. Results are **not validated** (lenient: the escape hatch is full-fidelity), typed as Distilled's output. Names follow the path (`scripts/resources.ts` documents the rule; `OVERRIDES` keeps the pre-effect-finance#146 names the rule would change, such as `Subscription.cancel`, and settles reserved words, singletons and the names the rule gets wrong, following stripe-node: `voidCreditNote`, `Billing.CreditGrant.voidGrant`, `Apps.Secret.delWhere` (it deletes by name and scope; every `del` deletes by id), `CreditNote.listPreviewLines`, `Tax.Settings.update`). A `/v2` module's params go out as a JSON body (Distilled's encoding; `StripeHttp`'s `DELETE`-to-query move applies only to form bodies), and its list is a `{ data, next_page_url }` page, which the planner reads as a list. `Treasury.ts` is a hand-written barrel over the ten `Treasury.*` modules; the root `index.ts` re-exports every other resource module, flattened (`BillingMeter`, `V2CoreAccount`).
- **Capability layers** — `StripePayments.customersLayer` … `refundsLayer`, `checkoutSessionsLayer`, `billingPortalSessionsLayer`, `capabilities` (all of them over Distilled's `Credentials` and an `HttpClient`, at the default policy), `layer` / `layerFromEnv` / `layerConfig` (credentials and policy from configuration; need an `HttpClient`). They map neutral params onto the Distilled operation's input (`omitUndefined`, since Distilled's input types declare bare `?: T`; a path id is refused unless it is a non-empty string; the neutral `idempotencyKey` of a create / confirm becomes `Idempotency-Key` after `IdempotencyKey.validate`; without one, a retryable `POST` gets a generated key shared by its attempts) and **decode** each response with a `Schema` narrowed to the fields they read (`internal/mapping.ts`), so a malformed 2xx fails with `PaymentProviderError`.
- **Webhook** — `Webhook.verify` is the default verifier: WebCrypto HMAC-SHA256 (`internal/signature.ts`), constant-time compare, a tolerance window read from `Clock`, then a lenient `Schema` decode of the envelope; `decodeHandledEvent` narrows it to `handledEventTypes`. `Webhook.constructEvent` / `constructEventAsync` wrap the SDK verifier and stay as the optional alternative: they need `Webhook.StripeService`, an SDK client the program builds and provides. The signing secret is a `Redacted` and never reaches a `SignatureVerificationError`.
