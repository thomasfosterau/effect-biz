### Minor Changes

- [#212](https://github.com/thomasfosterau/effect-biz/pull/212) [`67b0f17`](https://github.com/thomasfosterau/effect-biz/commit/67b0f17a354306440a550c244f7aaecc4366af8a) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add authorisation through effect-auth's policy kernel ([#130](https://github.com/thomasfosterau/effect-biz/issues/130)). `@thomasfosterau/effect-biz/Authorization` is the one subpath that imports `@thomasfosterau/effect-auth`, a new optional peer (`^0.2.0`). `authorize(action, resource)` asks effect-auth's `Authorizer` whether the `CurrentPrincipal` may perform a `"resource:action"` action on an `EntityRef`; a denial is `BizError.Forbidden` and any other Authorizer failure is `Unavailable`. `catalogue` declares a module's actions (`company` is core's: `company:create`, `read`, `update`, `archive`, `restore`), and `fragment` / `model` build effect-auth's `AuthorizationModel` from catalogues. `composeResolvers` / `layerResolvers` build one `EntityResolver` from per-type module resolvers, resolving transitive ancestors across them. `toActor`, `currentActor`, `withActor` and `layerActor` derive `Actor.CurrentActor` from the `CurrentPrincipal` (system principals become system actors). `layerPermissive` is an `Authorizer` that allows everything, for tests. `BizError.Forbidden` gains an optional `trace` (`Option<DecisionTrace>`, an omitted key on the wire): the decision's reason and its determining policies (`DeterminingPolicy`), never the principal.

- [#197](https://github.com/thomasfosterau/effect-biz/pull/197) [`92b1804`](https://github.com/thomasfosterau/effect-biz/commit/92b18047d5fc65efada2e09e6462adba3f6790ef) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add exact numbers and money. `@thomasfosterau/effect-biz/Decimal` is a `BigDecimal` schema that encodes as a canonical decimal string (never an exponent or a JSON number), with `make`, `fromString`, `zero`, `one`, `format` and a policy-rounded `divide`. `Rounding` carries `RoundingMode` (Effect's modes) and `RoundingPolicy`, and `round`. `Quantity` (an amount of a `UnitCode`, `NonNegativeQuantity`, `add` / `subtract`), `Percentage` (`toFactor`, `fromFactor`, `of`) and `Rate` (a positive factor with `apply` and `invert`) build on them. `Currency` has the branded `CurrencyCode` and the one ISO 4217 `minorUnits` table, and `Money` is the exact money type (`add`, `subtract`, `sum`, `multiply`, `round`, `toMinorUnits`, `fromMinorUnits`, largest-remainder `allocate`, `Order`, `Equivalence`). A unit or currency mismatch is a `BusinessRuleViolation` (`core.unit-mismatch`, `core.currency-mismatch`) in a `Result`, never a throw.

- [#214](https://github.com/thomasfosterau/effect-biz/pull/214) [`c921cc7`](https://github.com/thomasfosterau/effect-biz/commit/c921cc7a5fba6ffd1cb9ad7f2defdf56afb405ce) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add domain events, the transactional outbox, the dispatcher and idempotent subscribers ([#30](https://github.com/thomasfosterau/effect-biz/issues/30)). `./DomainEvent` defines an event type's versions (`make`, and `evolve` with an upcaster from the previous version), the JSON-safe `Envelope` (`EnvelopeFromJson`), and correlation and causation through `CurrentCorrelation`, `withCorrelation` and `causedBy`. `./EventRecorder`'s `record` fills the envelope from the context (tenant, optional company, actor kind and id, correlation, a fresh `EventId`, `Clock`) and stages it into the outbox within the command's unit of work. `./Outbox` is the port (`append`, lease-based `claimBatch`, `markDispatched`, `markFailed`, `deadLetters`) with per-(entry, subscriber) delivery state and per-aggregate ordering, and `layerMemory`. `./Subscriber` builds named handlers made exactly-once by the `Inbox` port (`layerInboxMemory`), whose mark commits with the handler's writes. `./Dispatcher` claims and delivers batches with exponential backoff and dead letters (`make`, `runOnce`, `drain`, `layer` with a scoped relay fiber, `layerOnDemand`). `./testing` adds `eventsContract`.

- [#197](https://github.com/thomasfosterau/effect-biz/pull/197) [`65864e3`](https://github.com/thomasfosterau/effect-biz/commit/65864e345fe0a068b9bca047adec021f9d7649b7) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add the first platform-foundation modules. `@thomasfosterau/effect-biz/Id` declares branded entity ids (`Id.make("PartyId")`: lower-case UUIDv7 strings, not assignable across kinds) and generates them from the `IdGenerator` service (`Id.generate`), with `Id.layer` (UUIDv7 from `Clock` and `Random`, increasing within a millisecond, deterministic under `TestClock` and a seeded `Random`) and `Id.layerSequential` for tests. `@thomasfosterau/effect-biz/BizError` is the error channel every module shares: `NotFound`, `AlreadyExists`, `ValidationError`, `ConcurrencyConflict`, `InvalidTransition`, `Forbidden`, `BusinessRuleViolation` and `Unavailable`, the `BizError` union schema, `isRetryable`, `httpStatus`, and `decodeUnknown` / `fromSchemaError` to turn a `Schema` failure into a path-addressed `ValidationError`.

- [#215](https://github.com/thomasfosterau/effect-biz/pull/215) [`6ef824b`](https://github.com/thomasfosterau/effect-biz/commit/6ef824b7a21173c5fec5ac24c8c139a445b670e0) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add document numbering sequences ([#31](https://github.com/thomasfosterau/effect-biz/issues/31)). `@thomasfosterau/effect-biz/NumberSequence` defines a `SequenceDefinition` per company and `DocumentType`: a `Pattern` of text and tokens (`{YYYY}`, `{YY}`, `{MM}`, `{FY}` and `{FYY}` for the fiscal year named by the year it ends in, `{COMPANY}` and exactly one `{#}` counter), a padding, a `ResetPeriod` (`"never"`, `"yearly"`, `"fiscal-yearly"`, `"monthly"`, in the company's time zone) and a `NumberingMode`. `define` creates or updates a definition, stored per tenant behind the `SequenceDefinitions` port (`get`, `list`). `next` issues a `DocumentNumber` through the `NumberSequences` port: in gap-less mode the counter write is staged and guarded in the command's `UnitOfWork` batch, so concurrent commands never share a number and a rolled-back command consumes none; in gaps-allowed mode it commits at once. `layerMemory` is the in-memory implementation; `periodOf`, `advance`, `format` and `fiscalYearOf` are the pure steps a SQL layer shares. `./testing` adds `numberSequencesContract`.

- [#210](https://github.com/thomasfosterau/effect-biz/pull/210) [`1d31921`](https://github.com/thomasfosterau/effect-biz/commit/1d319218d0d9bae289bd1202cce8781952df91f0) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add the repository conventions ([#28](https://github.com/thomasfosterau/effect-biz/issues/28)). `./Repository` defines `Port<A, I>` (`get`, `getMany`, `find`, `insert`, `update`, `archive`, `restore`, every method tenant-scoped and every write version-guarded) and `Deletable`; `./Audit` the `AuditFields` every stored entity carries (`createdAt`, `createdBy`, `updatedAt`, `updatedBy`, `version`, `archivedAt`), with `created`, `stamp` and `next`; `./Query` a typed filter and sort spec (`eq`, `in`, `range`, `search`, `archived`, `sort`) and its pure interpreter `run`; `./Page` keyset paging (`Page<A>`, opaque `Cursor`s, `limit` 50 by default, 500 at most); `./Memory` the tenant-partitioned in-memory store (`makeStore`, `rows`, `modify`, `repository`); and `./testing` the runner-agnostic contract suite (`repositoryContract`, `ContractFailure`). `Company` now carries `audit: AuditFields` instead of `version`, `Company.create` requires `CurrentActor`, `CompanyRepository` is a `Repository.Port` (adding `getMany`, `find`, `archive` and `restore`, with `Company.find` / `archive` / `restore` accessors), `list` returns only active companies, and `Company.layerMemory` is built on `./Memory`.

- [#209](https://github.com/thomasfosterau/effect-biz/pull/209) [`e353507`](https://github.com/thomasfosterau/effect-biz/commit/e35350789f52f6a44c5914155d5d0d9d7c3f5cd9) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add tenancy, companies and actors ([#26](https://github.com/thomasfosterau/effect-biz/issues/26)): `./Tenancy` (`TenantId`, `CompanyId`, `TenantContext`, `CompanyContext`, `currentTenant`, `currentCompany`, `withTenant`, `withCompany`), `./Company` (the `Company` entity with `Registration`, `CountryCode` and `FiscalYearStart`, the tenant-scoped, version-guarded `CompanyRepository` port, `create` / `get` / `list` / `update`, and `layerMemory`) and `./Actor` (`Actor`, `CurrentActor`, `current`, `system`, `withActor`).

- [#211](https://github.com/thomasfosterau/effect-biz/pull/211) [`40091f7`](https://github.com/thomasfosterau/effect-biz/commit/40091f739f67e1fb35f1f33681deef3359489897) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add the unit of work ([#29](https://github.com/thomasfosterau/effect-biz/issues/29)). `./UnitOfWork` defines the `UnitOfWork` service and its `transaction` accessor: a service wraps each command in it, the command's writes are staged (version-guarded) and committed as one atomic batch when it succeeds, nothing applies when it fails or is interrupted, nested transactions join the outer one, and a batch whose guard fails at commit is retried from the load step with bounded, jittered exponential backoff before failing with `ConcurrencyConflict` (`Options`: `attempts`, `backoff`). `makeJournal`, `stage` and `make` let another implementation (a SQL layer) stage its own write type; `layerMemory` / `makeMemory` commit the in-memory stores' writes in one `Effect.tx`. `./Memory` stores are now `TxRef`s: `Memory.modify` is replaced by `Memory.put` (one row guarded by the version it must still be at, staged into the open transaction or committed at once), and `makeLog` / `append` / `entries` add an append-only, outbox-shaped store; reads see committed rows only. `./testing` adds `unitOfWorkContract` and `UnitOfWorkSubject`, the runner-agnostic suite for a unit of work over a repository and an event log.

- [#188](https://github.com/thomasfosterau/effect-biz/pull/188) [`5064e9b`](https://github.com/thomasfosterau/effect-biz/commit/5064e9b48a0e79a52ed40fa93e22dadb5a3fd787) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - The payments entities and errors (`Money`, `Customer`, `Product`, `Price`, `Recurring`, `PaymentIntent`, `Refund`, `Subscription`, `CheckoutSession`, `BillingPortal` and every `PaymentsError` member) are now nominal: each `Schema.Class` / `Schema.TaggedError` carries a `{ readonly brand: unique symbol }` brand. - [#203](https://github.com/thomasfosterau/effect-biz/pull/203) [`e1bcada`](https://github.com/thomasfosterau/effect-biz/commit/e1bcada94a33dd4b5fb9bc28f49058baf5453929) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Absence is an `Option` and a parameter bag member is a bare `?: T`: `T | null` and `T | undefined` no longer appear in the payments types.

  Core entity fields that were `T | null` are now `Option<T>` (their encoded form is unchanged: `Schema.OptionFromNullOr` still reads and writes `null`). `Customer`: `email`, `name`, `phone`, `description`. `Product`: `description`. `Price`: `productId`, `unitAmount`, `recurring` (an `Option<Recurring>`). `PaymentIntent`: `customerId`, `paymentMethodId`, `clientSecret`, `description`. `Subscription` item: `quantity`. `Refund`: `paymentIntentId`, `chargeId`, `reason`. A provider builds them with `Option.fromNullishOr`; a consumer reads them with `Option.match` / `Option.getOrElse`.

  `Page.nextCursor` is now a required `Option<string>` (`Some` when `hasMore`), not an optional `string`; pass its value on as the list params' `startingAfter`. A provider's page literal must set it (`Option.none()` on the last page).

  Every `CreateParams` / `UpdateParams` / `ConfirmParams` / `ListParams` member (and `CheckoutSession` line items' `quantity`, and `Price.CreateParams["recurring"]`'s `intervalCount`) is declared `readonly x?: T` instead of `readonly x?: T | undefined`. Under `exactOptionalPropertyTypes` a caller holding `undefined` now omits the key rather than passing it.

  `IdempotencyKey.validate` takes an optional `key?: string` and resolves to `Option<IdempotencyKey>` (`None` for no key) instead of `IdempotencyKey | undefined`.

  Stripe: `StripeHttpConfig`, `LayerConfigOptions`, `RequestOptions` / `CallOptions` and `Webhook.VerifyOptions` / `WebhookConfig` members drop `| undefined` (`VerifyOptions.header` is now `header?: string`: omit it, rather than pass `null` or `undefined`, when the request carried no `Stripe-Signature`). The raw resource modules' trailing `options?: RequestOptions` is unchanged. In the semver-exempt `Payments.internal`, helpers that answered `T | undefined` (`scaleToMinor`, `parseDecimal`, `formatDecimal`, `stringField`) answer `Option<T>`, `epochSecondsOf` takes an `Option<string>`, and `pageNumberedList` takes its params as a required object and lists with `(page?: number)`.

  Error classes: every field that may be absent is now an `Option` (`Schema.OptionFromOptionalKey`, so the encoded form, over the wire and RPC, is still an omitted key; a constructor call may leave the field out, which is `None`). The fields: `PaymentProviderError` `code`, `statusCode`, `cause`; `PaymentAuthenticationError` `statusCode`; `PaymentRateLimitError` `retryAfter`; `PaymentInvalidRequestError` `param`, `statusCode`; `PaymentNetworkError` `cause`; `PaymentsUnavailable` `provider`; `SignatureVerificationError` `header`, `payload`; `BusinessRuleViolation` `details`. Pass `Option.some(x)` to set one and read it with `Option.match` / `Option.getOrElse`.

### Patch Changes

- [#187](https://github.com/thomasfosterau/effect-biz/pull/187) [`1a93ba9`](https://github.com/thomasfosterau/effect-biz/commit/1a93ba9404864fbe72869a3efda163b7613854ad) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Payments schemas no longer use `Schema.Number`. Minor-unit amounts (`Money.amount`, `unitAmount`, refund and payment-intent amounts), quantities, interval counts, epoch-second timestamps and HTTP status codes now decode with `Schema.Int`, and `PaymentsError.retryAfter` with `Schema.Finite`. Decoding therefore rejects `NaN` and `Infinity`, and rejects fractional values wherever `Schema.Int` applies; the same holds for the Stripe mapping and webhook schemas.
